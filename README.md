# j-delete-comment

代码注释四分类治理技能（Claude Code Skill）。它把「删注释」从一次性清理变成可复用、可验证、可回查的工程流程。

方法来源：Matt Pocock 的「comments considered harmful」prompt 提出四类分流。Dijkstra、Kent Beck、Michael Nygard 的实践提供了底色。本技能在四类分流之上补了四个工程环节：白名单裁决、双分类一致性抽样门、批量处置的对账验证、无 ADR 体系项目的适配分支。

## 工作流程

对指定范围的每一行代码注释：

1. 建白名单并裁决归宿（哪些注释受保护；决策类注释迁 ADR 还是留注释）
2. 全量枚举，产出单一事实源清单
3. 四分类并逐条附证据：同义反复 / 借口 / 过期 / 决策记录
4. 按类处置：同义反复与过期删除；借口删除并立修复工单；决策记录按裁决迁移或保留
5. 验证对账（diff 行数对账、类型检查、全量测试、反向抽查）
6. 写入逐条处置报告，给出注释量三行估算

## 依赖

运行期硬依赖：

- Claude Code，或任何支持 Skill 约定（frontmatter + markdown 正文）的编码代理环境
- 目标项目是 git 仓库（过期判定用 `git log -S`，对账用 `git diff`）
- 目标项目有类型检查与测试命令（验证步骤需要；无法运行时可声明跳过）

无代码依赖：本技能是指令文件，不安装 npm / pip 包。

可选依赖：

- vitest 或 jest 项目可配「注释水位测试」（ratchet：注释总量只降不升）。不配不影响主流程。
- ESLint 项目可参考技能内的规则样例做 lint 封禁。技能只产建议，不改你的配置。

## 适应性

适用：

- 有 ADR 体系的项目（决策注释迁入 ADR）
- 无 ADR 体系的项目（第 0 步会问一次「迁 ADR 还是留注释」，并给推荐答案；也可从零建最小 docs/adr/）
- 项目规则约定「注释只写为什么」的项目（技能识别该约定，决策记录原位保留）
- 全库或单目录范围。注释量 100 条以上自动启用抽样一致性门。

语言适配：技能的枚举口径默认 `//` 行注释与 `/* */` 块注释（TS / JS / CSS 系）。C 系、Python（`#`）、Ruby、Shell 的注释语法不同。用这些语言前，先改枚举器脚本的提取规则。四分类与治理流程本身与语言无关。

已知局限：

- 枚举器用引号配平嗅探区分注释与字符串。XML/模板字符串里的 `//` 会被误收。这类行会落进存疑清单，处置前人工扫一眼即可。
- 类别判定依赖 LLM 语义判断。抽样门（30 条双分类 Cohen's kappa）是质量底线，替代不了人工复核存疑清单。
- 本技能删注释，不修注释所辩护的 hack。它只立工单，修复是另一个流程。

## 安装

拷贝本仓库的 `delete-comment` 目录到：

- 全局：`~/.claude/skills/`（所有项目可用）
- 项目级：`<repo>/.claude/skills/`（仅该项目）

## 使用

在 Claude Code 会话中输入：

```
/delete-comment <范围>
```

例：`/delete-comment backend/src frontend/src` 或 `/delete-comment src/services`。

调用即执行（非 dryrun）。第 0 步的归宿裁决是唯一可能停下来问你的点。其余流程自动走完，结尾给出报告路径与逐条处置表。
